## Размышления

**Почему наивный прогон проверялся тем же чек-листом.** Соблазн был сравнить
свой результат, проверенный придирчиво, с чужим, оценённым по описанию автора.
Это дало бы красивую картинку и ничего не стоило бы. Поэтому наивный результат
поднят отдельным сервером (`python3 -m http.server 8765`) и прогнан по тем же
требованиям задания. Селекторы, разумеется, другие — приложение другое;
совпадают проверяемые требования, а не разметка.

### Мой тест дважды соврал, и оба раза в мою пользу

Первый прогон наивного дал 7 из 13. Разбор показал, что два падения —
дефекты проверки, а не проверяемого:

1. **«Ячейки дней достижимы с клавиатуры» — ложное падение.** Критерий искал
   в доступном имени слово «день» или класс `cell`. В наивном прогоне ячейки
   подписаны «Вт 11: не отмечено» — клавиатурой они достижимы прекрасно.
   Исправлено на поиск «отмечено / выполнено», проверка проходит.
2. **«Фокус визуально обозначен» — сначала ложное падение, потом ложное
   прохождение.** Первая версия смотрела только `outline` и падала. Добавил
   `box-shadow` — и проверка прошла, потому что `box-shadow` там есть…
   `rgba(0, 0, 0, 0)`, то есть прозрачный. Проверка на «свойство не пустое»
   вместо «видно ли это глазом» — ровно та ошибка, за которую задание ругает
   отчёты агентов.

Пришлось замерять честно, отдельным скриптом, с сравнением двух приложений:

| | Наивный прогон | По спецификации |
|---|---|---|
| `outline` на ячейке в фокусе | `solid 3px rgba(0, 0, 0, 0)` | `solid 2px rgb(59, 69, 214)` |
| `box-shadow` | `none` | внутреннее кольцо + подсветка |

В наивном контур объявлен, но полностью прозрачный: клавиатурный пользователь
не видит, где находится. Это настоящий дефект, и он не был бы найден
ни глазами по скриншоту, ни проверкой «есть ли CSS-свойство».

Урок, который дороже самой находки: **проверка тоже требует проверки.**
Три раза подряд я получал цифру, которая выглядела убедительно и была неверной.

### Итог по двум прогонам

- По спецификации: **25 из 25**.
- Наивный: **9 из 13**.

Что наивный прогон реально не умеет (проверено, а не вычитано из кода):

1. **Дубли не отсеиваются.** «Зарядка» и «зарядка» сосуществуют.
2. **Состояние ошибки недостижимо из интерфейса.** Импорта нет, вызвать
   ошибку руками нечем — обязательное третье состояние задания отсутствует.
3. **Битое хранилище проглатывается молча.** Экран поднимается пустым,
   пользователю не сказано, что его данные не прочитались. Формально «не упало»,
   по сути — потеря данных без предупреждения.
4. **Чужая структура принимается за данные.** `[{"foo":1},{"bar":2}]` прошло
   как две привычки: проверяется только `Array.isArray`, элементы не валидируются.
5. **Фокус на ячейках невидим** (замер выше).

В чём наивный прогон не уступает: пустое состояние есть, перезагрузку переживает,
на 360 px не разъезжается, консоль чистая, ячейки достижимы с клавиатуры,
пустое имя отклоняет. Это честно стоит записать: разрыв не в «работает —
не работает», а в поведении на краях.

## Финальный вердикт

Пункт закрыт: оба прогона проверены одним чек-листом, результаты сохранены.

Что осталось: аудит кода независимой сессией, README, сравнение прогонов
текстом (сессия 6).

Ограничение: чек-лист живёт вне репозитория, в папке сессии. Для сдачи это
нормально — вывод сохранён, — но в живом проекте он должен лежать рядом
с кодом и гоняться в CI, иначе через неделю о нём никто не вспомнит.
