# Спецификация — «Неделя привычек»

- **Дата:** 2026-08-17
- **Статус:** согласована в сессии 1, до написания кода

## Что делаем

Один экран в браузере: недельная сетка привычек. Пользователь заводит привычки,
отмечает выполнение по дням недели и видит текущую серию по каждой.

## Для кого и зачем

Для человека, который ведёт несколько личных привычек и хочет видеть не список дел
на сегодня, а **картину недели целиком**: где серия держится, а где порвалась.
Бумажный трекер это показывает, а приложение с чекбоксом «на сегодня» — нет.

Данные личные и остаются в браузере: ни аккаунта, ни сервера, ни синхронизации.

## Сценарии

1. **Первый заход.** Экран пуст, объясняет, что здесь будет, и предлагает добавить
   первую привычку. Никаких пустых сеток и нулей.
2. **Добавление привычки.** Пользователь вводит название, привычка появляется
   строкой в сетке текущей недели, все семь ячеек пустые.
3. **Отметка дня.** Клик или Enter/Space на ячейке переключает отметку.
   Серия пересчитывается сразу.
4. **Отметка задним числом.** Забыл отметить вторник — отмечает его сегодня.
   Любой день текущей недели редактируется одинаково.
5. **Просмотр прошлых недель.** Стрелка «назад» показывает предыдущую неделю
   с сохранёнными отметками; они тоже редактируются.
6. **Удаление привычки.** С подтверждением: удаляются и её отметки, отменить нельзя.
7. **Перезагрузка страницы.** Всё на месте: привычки, отметки, выбранная тема.
8. **Экспорт.** Пользователь скачивает свои данные одним JSON-файлом.
9. **Импорт.** Загружает ранее выгруженный файл — данные заменяются.
10. **Импорт испорченного или чужого файла.** Экран не падает: показывает ошибку
    с причиной, текущие данные остаются нетронутыми.
11. **Испорченное хранилище.** localStorage повреждён снаружи — экран поднимается
    в пустом состоянии с предупреждением, а не белым полотном.

## Состояния

Три обязательных состояния, каждое достигается **руками из интерфейса**:

| Состояние | Когда | Что видно | Как достичь руками |
|---|---|---|---|
| **Пусто** | привычек нет | заголовок, объяснение, форма добавления, кнопка «Заполнить примером» | первый заход или удаление всех привычек |
| **Есть данные** | ≥ 1 привычки | сетка 7 дней × N привычек, серии, навигация по неделям | добавить привычки или нажать «Заполнить примером» (7 привычек с историей) |
| **Ошибка** | импорт файла не прошёл проверку | баннер поверх текущего экрана: что именно не так и в каком поле, единственное действие — «Понятно» | импортировать `evidence/broken.json` или `evidence/foreign.json` |

Ревью спецификации (находка 4) показало, что «ошибка» изначально смешивала
два разных случая. Они разведены:

- **Ошибка импорта** — неблокирующее наложение поверх того состояния, в котором
  экран сейчас. Данные **не трогаются**, кнопки «Сбросить» на этом баннере нет:
  предлагать снос валидных данных в ответ на плохой файл — ловушка для пользователя.
- **Испорченное хранилище** — экран поднимается в состоянии «Пусто» и показывает
  отдельное предупреждение с кнопкой «Сбросить данные». Это не третье состояние,
  а «Пусто» с предупреждением: разбирать нечего, показывать нечего.

Испорченным хранилище считается, если содержимое не разбирается как JSON,
либо не проходит схему, либо содержит неизвестную `version`.

Дополнительно к трём обязательным:

- **Пустой результат недели** — привычки есть, но на выбранной неделе ни одной
  отметки: сетка показывается пустой. Это не отдельное состояние экрана,
  а нормальный вид сетки. Счётчик серии при этом **не обнуляется**: он всегда
  считается на сегодня и от выбранной недели не зависит (см. правила ниже).
  Исходно здесь было написано «серии нулевые» — это противоречило правилу,
  добавленному после ревью; поймал аудит кода, находка 5.
- **Подтверждение удаления** — оверлей поверх экрана, закрывается по Esc.

## Модель данных

Два ключа в localStorage — данные и тема хранятся **раздельно** (решение
по находке 12 ревью: импорт чужого файла не должен менять оформление,
а разбор битого хранилища — терять выбранную тему).

`habit-tracker/v1` — данные:

```json
{
  "version": 1,
  "habits": [
    { "id": "h1", "name": "Зарядка", "createdAt": "2026-08-10" }
  ],
  "checks": {
    "h1": ["2026-08-10", "2026-08-11", "2026-08-13"]
  }
}
```

`habit-tracker/theme` — строка `light` | `dark` | `system`. В экспорт не входит,
импортом не затрагивается.

`habit-tracker/v1.broken` — диагностический след: сюда кладётся содержимое
`habit-tracker/v1`, которое не удалось прочитать. Перезаписывается при каждом
новом сбое, в интерфейсе не показывается и в экспорт не попадает.

Даты — строки `YYYY-MM-DD` по локальному календарю. Отметка либо есть, либо нет:
третьего значения не существует.

### Схема импорта

Файл принимается, только если выполнено всё:

| Поле | Требование |
|---|---|
| `version` | ровно `1`. Другое значение — ошибка с текстом про версию |
| `habits` | массив; каждый элемент — объект с `id` (непустая строка, уникальна), `name` (строка после `trim` от 1 до 40 символов, уникальна без учёта регистра), `createdAt` (дата в формате `YYYY-MM-DD`) |
| `checks` | объект; ключи — строки, значения — массивы дат `YYYY-MM-DD` |
| даты | должны быть реально существующими: `2026-02-30` и `2026-13-01` отклоняются |
| будущие даты | в `checks` запрещены — иначе через импорт протаскивается состояние, которое руками собрать нельзя |
| лимит | не более 20 привычек |

Мягко, без ошибки: неизвестные поля игнорируются; повторы дат внутри массива
схлопываются; ключи `checks`, не ссылающиеся ни на одну привычку, отбрасываются
(осиротевшие отметки не влияют на то, что видит пользователь).

Импорт заменяет данные целиком, не сливает.

## Правила, которые нельзя решать молча

- **Неделя начинается с понедельника.** Отображаются семь дней от понедельника
  до воскресенья.
- **День — локальный,** начинается в 00:00 по часовому поясу устройства.
  Пересчёта между поясами нет.
- **Будущие дни не отмечаются.** Ячейки будущих дней текущей недели неактивны,
  не получают фокус и визуально отличаются. Навигация вперёд дальше текущей
  недели заблокирована.
- **Серия** — число подряд идущих отмеченных дней, заканчивающееся сегодняшним
  или вчерашним днём. Пропуск обнуляет её сразу, заморозок нет.
- **Сегодняшний день не ломает серию.** Пока сегодня не наступила полночь,
  неотмеченный сегодняшний день серию не обрывает: она считается по вчерашний.
  Отметил сегодня — серия выросла на единицу.
- **Название привычки:** обрезается по краям (`trim`), пустое не принимается,
  максимум 40 символов, дубликат без учёта регистра отклоняется с ошибкой
  рядом с полем.
- **Импорт валидируется по схеме,** а не по `JSON.parse`. Схема — выше,
  в разделе «Модель данных».
- **Испорченное хранилище не роняет экран:** при ошибке чтения приложение
  поднимается в пустом состоянии и говорит об этом, старое значение сохраняется
  под ключом `habit-tracker/v1.broken`.

Добавлено по итогам ревью спецификации:

- **Дата берётся из локальных компонент**, а не через `toISOString`.
  Это прямой запрет: `new Date().toISOString().slice(0, 10)` вернёт дату по UTC
  и сдвинет «сегодня» для всех, кто не в нулевом поясе, — ровно там, где спека
  требовательнее всего. Арифметика недель — шагом по дням через конструктор
  `Date(y, m, d ± n)`, а не прибавлением миллисекунд: иначе переход на летнее
  время даст сдвиг на час и потерянный день.
- **Смена суток при открытой вкладке.** Экран пересчитывает «сегодня» при
  возврате фокуса на вкладку (`visibilitychange` и `focus`). Если приложение
  оставили открытым на ночь, после возврата ячейки, неделя и серии
  соответствуют новой дате, а не дате загрузки.
- **Серия всегда считается на сегодня** и не зависит от того, какая неделя
  открыта. Листание назад меняет сетку, но не число серии. Серия считается
  по всей истории, поэтому может быть больше семи — это не рассинхрон с сеткой,
  а осознанное поведение: рядом с числом стоит подпись «подряд», а не «за неделю».
- **`createdAt` — справочное поле.** Оно не ограничивает редактирование:
  отмечать можно любой прошедший день, в том числе до создания привычки.
  Человек заводит привычку в среду, а бегает с понедельника — это нормальный
  случай, а не ошибка ввода.
- **Пример строится относительно сегодняшней даты**, а не жёстко зашитыми
  датами: часть отметок на текущей неделе, часть на прошлой, ни одной в будущем,
  `createdAt` не позже самой ранней отметки. Иначе критерии приёмки про серии
  проверялись бы только 17 августа 2026 года.

### Доступность — уточнено ревью

- **Навигация по сетке — стрелками, а не одним Tab.** При 20 привычках Tab-цепочка
  из 140 ячеек делает клавиатурный проход бессмысленным. Сетка — одна остановка
  Tab (roving tabindex), внутри перемещение стрелками, `Home` и `End` — на края
  строки. Tab ходит между зонами: шапка, навигация по неделям, сетка, форма.
- **Оверлей удаления:** при открытии фокус уходит внутрь, из оверлея не выпадает,
  при закрытии возвращается на кнопку, которая его открыла.
- **Баннеры ошибок и предупреждений** живут в `aria-live` области, иначе
  для скринридера ошибка импорта просто не существует.
- **Доступное имя ячейки** — привычка, дата и состояние, а не «кнопка».

### Раскладка на 360 px — уточнено ревью

Ревью справедливо заметило (находка 7), что требование «нет прокрутки +
семь читаемых колонок + попадание пальцем» на 360 px невыполнимо в одну строку:
семь ячеек по 44 px — это уже 308 px, а в строке ещё название, серия и удаление.

Решение: **на узких экранах строка перестраивается в карточку.** Название,
серия и кнопка удаления — верхней строкой карточки, семь ячеек — под ними
отдельным рядом на всю ширину. Ячейка занимает `1fr` от ширины карточки
и не меньше 36 px по высоте. Порог перестроения — 720 px.

На 1440 px раскладка табличная: колонка названия фиксирована, дни равной ширины,
контейнер ограничен по максимальной ширине и центрирован — растягивать сетку
на весь экран бессмысленно.

## Чего точно не делаем

- Графиков, диаграмм и любой аналитики сверх числа серии.
- Напоминаний, уведомлений, запроса разрешений браузера.
- Аккаунтов, сервера, синхронизации между устройствами.
- Категорий, тегов, цветов и иконок привычек.
- Количественных привычек («3 из 5 стаканов») — отметка только бинарная.
- Редактирования названия после создания: удалить и создать заново.
- Заморозок серии, целей на неделю, наград и мотивационных сообщений.
- Drag-and-drop сортировки привычек.
- Отметки будущих дней.
- PWA, офлайн-манифеста, установки на домашний экран.

## Допущения

- **Хранилище — localStorage, не файл мок-данных.** Задание допускает оба варианта;
  выбран localStorage, потому что перезагрузка страницы должна сохранять то,
  что пользователь наклацал руками, а мок-файл этого не даёт.
- **Лимит 20 привычек.** Сетка 7×N перестаёт читаться раньше, чем упрётся
  в производительность; ограничение честнее, чем разъезжающийся экран.
- **Тёмная тема по `prefers-color-scheme`**, с переключателем на три положения
  (светлая / тёмная / системная). Выбор хранится вместе с данными.
- **Одна вкладка.** Синхронизация между вкладками через событие `storage`
  не делается: последняя запись побеждает.
- **Тестов нет, проверка ручная и через Playwright MCP.** Задание требует
  доказательства запуска, а не покрытия; при 4–5 часах на весь цикл тестовый
  контур съел бы время у проверки состояний.

## Решения по итогам независимого ревью

Спецификация проверена чистой сессией без истории обсуждения **до написания кода**.
Полный текст находок — в `evidence/spec-audit.md`. Вердикт по каждой:

| # | Находка | Вердикт |
|---|---|---|
| 1 | Не описан переход суток при открытой вкладке | **Принято.** Пересчёт по `visibilitychange` и `focus` |
| 2 | Серия неоднозначна при просмотре прошлых недель | **Принято.** Серия всегда на сегодня, от выбранной недели не зависит |
| 3 | Серия может быть длиннее видимой недели | **Принято частично.** Считаем глобально по истории; рассинхрон снимаем подписью «подряд», а не ограничением окна |
| 4 | Состояние «Ошибка» смешивает три разных экрана | **Принято, самая важная находка.** Разведены ошибка импорта (наложение, данные целы) и битое хранилище («Пусто» + предупреждение). Убрана кнопка «Сбросить» с баннера импорта |
| 5 | Валидация импорта описана лозунгом, без правил | **Принято.** Схема выписана таблицей, включая запрет будущих дат |
| 6 | `createdAt` без назначенной роли | **Принято.** Объявлено справочным, редактирование не ограничивает |
| 7 | 360 px: тач-цели не совмещаются с 7 колонками | **Принято.** Строка перестраивается в карточку до 720 px |
| 8 | UTC-ловушка в `toISOString` | **Принято.** Прямой запрет в спеке, плюс запрет арифметики по миллисекундам |
| 9 | Доступность оверлея и объявление ошибок | **Принято.** Фокус-трап, возврат фокуса, `aria-live` |
| 10 | Tab через 140 ячеек | **Принято.** Roving tabindex со стрелками |
| 11 | Пример на две недели с абсолютными датами | **Принято.** Пример строится относительно сегодня |
| 12 | Импорт молча меняет тему | **Принято.** Тема вынесена в отдельный ключ |
| 13 | Жизненный цикл `.broken` не описан | **Принято частично.** Объявлен чисто диагностическим следом: перезаписывается, в UI не показывается, в экспорт не входит. Механизма «разбора» не делаем — это было бы отдельной функцией |
| 14 | Чужой валидный формат может выглядеть как повреждение | **Принято.** Дано определение «испорченного» |

Отклонённых находок нет. Это не признак хорошей спеки: ревьюер работал
по тексту, где половина решений просто отсутствовала, и находил дыры,
а не спорные трактовки. Настоящий спор начнётся на ревью кода.

## Критерии приёмки

- [ ] Экран открывается по инструкции из README на чистой машине.
- [ ] Первый заход в браузере без данных показывает пустое состояние
      с формой добавления, а не пустую сетку.
- [ ] Кнопка «Заполнить примером» даёт 7 привычек с отметками за две недели;
      состояние «есть данные» достигнуто без правки кода.
- [ ] Импорт файла `evidence/broken.json` показывает баннер ошибки,
      существующие привычки при этом не пропадают.
- [ ] После F5 привычки, отметки и выбранная тема на месте.
- [ ] Отметка вторника задним числом меняет серию согласно правилу
      «пропуск обнуляет».
- [ ] Неотмеченный сегодняшний день не обнуляет серию, набранную по вчера.
- [ ] Ячейки будущих дней не кликаются и не получают фокус с клавиатуры.
