# Неделя привычек

Домашнее задание после занятия 1, направление **Frontend** — «Интерактивный экран
с состояниями».

Один экран в браузере: недельная сетка привычек. Заводите привычки, отмечаете дни
(в том числе задним числом), видите серию по каждой. Данные живут в localStorage,
сервера и аккаунтов нет.

Задание выбрано из списка (вариант «личный трекер привычек»), а не своё:
пет-проекта под рукой не было, а трекер даёт естественные три состояния
и нетривиальную логику на границе суток — там, где агент ошибается сам собой.

---

## Как запустить

Нужен Node.js 20 или новее (разрабатывалось на 24.3.0, npm 11.4.2).

```bash
cd app
npm install
npm run dev
```

Откройте адрес, который напечатает Vite — обычно `http://localhost:5173`.
Если порт занят, Vite сам возьмёт следующий свободный и скажет какой
(во время разработки было именно так: 5173 занимал другой проект, работа шла на 5174).

Другие команды:

```bash
npm run build      # сборка: tsc -b && vite build
npm run preview    # посмотреть собранное
npx oxlint         # линтер
```

Автотестов в проекте нет — осознанное решение, см. «Что упрощено».
Проверка выполнялась скриптом Playwright, вывод сохранён в `evidence/`.

Инструкция проверена на свежем клоне репозитория, а не на рабочей копии:
`git clone` → `npm install` → `npm run build` → `npm run dev` → весь чек-лист
из 30 проверок прошёл против клона.

## Как посмотреть все три состояния

Задание требует, чтобы каждое состояние достигалось руками из интерфейса.

| Состояние | Что сделать |
|---|---|
| **Пусто** | Открыть приложение первый раз (или удалить все привычки) |
| **Есть данные** | Нажать «Заполнить примером» — 7 привычек с историей за две недели |
| **Ошибка** | Нажать «Загрузить» и выбрать `evidence/broken.json` или `evidence/foreign.json` |

Первый файл — синтаксически битый JSON, второй — валидный JSON чужой схемы.
Это разные ветки кода: один падает на разборе, другой проходит разбор и
отсеивается уже проверкой схемы. Данные на экране при этом не меняются.

Чтобы увидеть поведение при испорченном хранилище, откройте консоль браузера:

```js
localStorage.setItem('habit-tracker/v1', '{ это не json');
location.reload();
```

Экран поднимется пустым с предупреждением, а не белым полотном.

## Что сделано

- Недельная сетка: строка на привычку, семь дней от понедельника.
- Бинарная отметка дня, отметка задним числом, навигация по прошлым неделям.
- Серия: подряд идущие дни; сегодняшний неотмеченный день серию не рвёт.
- Три состояния интерфейса, каждое достижимо руками.
- Хранение в localStorage с валидацией по схеме при чтении и импорте.
- Экспорт и импорт данных файлом.
- Светлая, тёмная и системная тема; выбор хранится отдельным ключом.
- Клавиатура: сетка — одна остановка Tab, внутри стрелки, `Home` и `End`;
  фокус-трап и возврат фокуса в оверлее удаления; сообщения объявляются
  через `role="alert"` и `role="status"`.
- Адаптив: на ширинах до 720 px строка перестраивается в карточку.

## Чего сознательно нет

Список нецелей целиком — в `SPEC.md`. Коротко: графиков и статистики,
напоминаний, аккаунтов и синхронизации, категорий и тегов, количественных
привычек, редактирования названия, drag-and-drop, PWA.

## Что упрощено и что не проверено

Честный раздел, читайте его.

- **Автотестов нет.** Проверка — скрипт Playwright, он лежит вне репозитория,
  в папке сессии; в репозиторий попал только его вывод (`evidence/checklist-*.md`).
  Для сдачи этого хватает, для живого проекта — нет: чек-лист должен лежать
  рядом с кодом и гоняться в CI.
- **Синхронизация между вкладками не сделана.** Событие `storage` не слушается,
  две открытые вкладки затрут данные друг друга. Записано в допущениях спеки.
- **Часовые пояса проверены только логикой кода.** Ключи дат строятся из
  локальных компонент, `toISOString` запрещён явно, но прогона под другим
  системным поясом не было.
- **Переход на летнее время** обойдён конструкцией `Date(y, m, d ± n)`
  вместо арифметики миллисекунд, отдельного теста на это нет.
- **История коммитов не отражает ход работы.** По ходу разработки git
  намеренно не велся, репозиторий заведён в конце одним импортом. Значит,
  «SPEC.md написан до кода» подтверждается журналом в `sessions/`, а не
  датами коммитов. Это сознательный размен, и он не в мою пользу:
  задание прямо пишет, что по истории коммитов видно, как шла работа.
- **Лимит 20 привычек** выбран из соображений читаемости сетки, а не измерений.

## Наивный прогон и что изменила спецификация

В `naive/` лежит результат одного промпта «сделай трекер привычек» без
спецификации и без правил проекта. Он не правился.

**Наивный прогон оказался сильнее ожидаемого.** Модель сама сделала пустое
состояние, `100dvh` вместо `vh`, `prefers-reduced-motion`, тёмную тему,
`aria-pressed` на ячейках и `try/catch` вокруг чтения хранилища. Утверждение
«без спеки получается мусор» было бы неправдой.

Оба результата прогнаны по одному чек-листу требований задания:
**по спецификации 30 из 30, наивный 9 из 13** (`evidence/checklist-*.md`).

Что решила за меня модель в наивном прогоне:

| Решение | Наивный прогон | По спецификации |
|---|---|---|
| Стек | один HTML-файл без сборки | Vite + React + TS — выбор человека |
| Горизонт | последние 7 дней от сегодня | календарная неделя с понедельника |
| Дубли имён | разрешены | запрещены без учёта регистра |
| Валидация хранилища | `Array.isArray` верхнего уровня | схема с проверкой каждого поля |
| Чужие данные | `[{"foo":1}]` принимается за привычки | отклоняется с указанием причины |
| Состояние ошибки | нет | баннер, данные не трогаются |
| Битое хранилище | молча пустой экран | предупреждение и кнопка сброса |
| Фокус на ячейке | `outline` прозрачный — не видно | 2 px индиго + внутреннее кольцо |
| Импорт и экспорт | нет | есть |
| Навигация по неделям | нет | есть |

Где наивный не уступает: перезагрузку переживает, на 360 px не разъезжается,
консоль чистая, ячейки достижимы с клавиатуры, пустое имя отклоняет.

**Вывод.** Разница не в том, что один работает, а другой нет. Разница в краях:
что происходит с чужими данными, с испорченным хранилищем, с дублями, с фокусом.
Наивный прогон делает то, о чём его попросили; спецификация задаёт то,
о чём никто не просит вслух, — и именно это ломается у пользователя.

## Два независимых аудита

**Спецификацию** проверила чистая сессия **до** написания кода — 14 находок
(`evidence/spec-audit.md`). Четыре из них изменили архитектуру: состояние ошибки
было склеено из трёх разных экранов, кнопка «Сбросить данные» на баннере импорта
противоречила обещанию сохранности, тема лежала в одном ключе с данными,
`createdAt` висел без назначенной роли.

**Готовый код** проверила вторая чистая сессия, запущенная в режиме `plan`,
чтобы правки были запрещены механизмом, а не просьбой — 9 находок
(`evidence/code-audit.md`), все приняты и исправлены. Пять из девяти касались
доступности с клавиатуры — той части, которую я проверял внимательнее всего.
Одна из них возникла как прямое следствие починки предыдущего дефекта:
замена `disabled` на `aria-disabled` вернула фокус стрелкам и одновременно
разрешила ставить его на будущие дни, что запрещено отдельным критерием.
Вердикты по каждой находке — в `sessions/session-6.md`.

## Контраст

Замерен скриптом по WCAG 2.1 на фактически отрисованных цветах, в обеих темах
и на двух экранах — вывод в `evidence/contrast.md`. Узлов ниже нормы нет,
минимум **7.09:1** в светлой теме и **7.23:1** в тёмной, то есть выполнен
не только уровень AA (4.5:1), но и AAA (7:1).

До подъёма минимум составлял 4.72:1 — AA проходил, AAA нет. Правки точечные:
вторичный текст, отдельный токен для текста поверх зелёной подложки
(сам `--done` трогать нельзя, он работает заливкой под белым текстом)
и минимальный сдвиг акцента в обеих темах.

## Дизайн: до и после

Дизайн-проход выполнен **отдельной сессией** со скиллом `frontend-design`,
без единой правки логики. Скриншоты сняты на одних данных и одних ширинах:

- `evidence/before/` — до прохода
- `evidence/after/` — после

Что изменилось перечислением — в `sessions/session-4.md`. Коротко: две гарнитуры
вместо одной, 83 токена палитры вместо шести цветов, панели вместо плоского фона,
ячейки-«шаги» со свечением, «мостик» между соседними выполненными днями,
инлайновые SVG вместо символа `×`, усиленное кольцо фокуса.

Дизайн-сессия при этом **сломала адаптив и отчиталась, что не сломала**:
на 360 px появился перебор в 10 пикселей. Поймал прогон чек-листа, не глаза.

Второй её след нашёлся позже и глазами: ячейки получили `position: relative`
и `z-index` ради декоративного «мостика» между выполненными днями, а у оверлея
`z-index` не было — и сетка рисовалась поверх диалога удаления. Выглядело как
просвечивающий диалог, хотя заливка у него непрозрачная: он просто был снизу.
Третий след — там же: анимация появления страницы оставляет на `.page`
единичную матрицу `transform`, а это делает её блоком-контейнером
для `position: fixed`, и подложка диалога затемняла только колонку, а не окно.
Лечится порталом в `body`. Разбор — в `sessions/session-7.md`, там же два
неверных диагноза, которые я выдал до правильного.

Оба дефекта диалога нашёл человек, открыв приложение руками: ни автоматические
проверки, ни мои скриншоты их не поймали.
